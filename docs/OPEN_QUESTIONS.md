# Open Questions

## P0

### 是否允许清理测试生成的未跟踪 `pytest-of-unknown/` 目录？

- 为什么：规范 Python 测试包装器在当前 Windows 环境产生了该临时目录；此前的 `~/Python/...` 已按用户授权安全删除。
- 不确认的影响：目录继续污染 `git status`，但不影响 M9.1 运行。
- 当前推断：该目录是测试副产物，不属于产品源码；置信度高。
- 推荐：用户单独授权后验证绝对路径，再使用单一 PowerShell 流程删除；当前不删除、不提交。

### 是否授权 push M9.1 本地提交？

- 为什么：M9.1 实现已形成本地提交 `83b4e8f`，知识文档将形成独立本地提交，但尚未同步到远端。
- 不确认的影响：本机仓库可通过 Git 恢复，远端仍无法恢复 M9.1。
- 当前推断：应先由用户审阅本地提交和验证结果，再决定是否 push；置信度高。
- 推荐：push 与 release 分别授权；未经授权不执行。

## P1

### 哪些 provider/sidecar 是正式支持项？

- 影响：验收、文档承诺、凭据/风控/费用支持。
- 推断：默认 mock/offline；real/sidecar opt-in；置信度高。
- 推荐：逐项标记 supported/experimental/dev-only。

### 历史 workspace 的迁移与保留策略？

- 影响：数据丢失、备份、兼容期、隐私。
- 推断：应无损迁移并保留审计备份；完成度 UNKNOWN。
- 推荐：先只读 inventory + backup/restore drill。

### M10.1 Live 验收使用哪个 Provider、素材和数据源？

- 为什么：真实视频和平台研究会使用凭据、Cookie、网络与费用，必须形成明确 task scope。
- 不确认的影响：M10 只能保持离线/Fake Gateway 已验证，不能标记 DONE。
- 当前推断：使用“周十五蜂蜜露”已确认当前主图、一个现有视频 Provider，网页优先；XHS/抖音只在用户明确允许且 sidecar 可用时加入。置信度中。
- 推荐：用户确认 Provider、测试 workspace/素材、允许来源、Cookie 范围、图片/视频调用上限和执行窗口后，再开始 M10.1。

### M10 默认每次展示候选还是自动执行第一名？

- 为什么：影响运营人员的可控感、等待时间和费用。
- 不确认的影响：`adaptive` 当前按用户是否说“先看方案”决定，Live 体验仍需验证。
- 当前推断：默认内部评估后执行第一名；高费用视频先展示方案可能更适合内部运营。置信度中。
- 推荐：在 M10.1 用户验收中比较一次 direct 与一次 preview-first，再固定默认体验。
