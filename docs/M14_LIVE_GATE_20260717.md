## 10. Live Gate 执行顺序

1. 确认当前 task、plan hash、授权请求和 Brain hash 未漂移。
2. 取得上节具体外部披露授权后，批准同一个授权请求，不创建宽泛或跨任务授权。
3. 设置 `PRODUCT_CREATIVE_ENABLE_REAL_PROVIDER=1`，执行最多 5 次真实豆包图片生成。
4. 每次提交保存脱敏请求摘要、Provider task/result、耗时、attempt 和 receipt。
5. 完成逐镜头结果后执行本地 exact-main 合成，验证产品 plate hash、H.264/AAC、时长和镜头顺序。
6. 用豆包 VLM 对少量代表帧执行 M14 QA；确定性硬失败优先于模型判断。
7. QA 为 REPAIR 时只返修失败镜头；预算不足或超过两轮立即停止。
8. 独立执行一次 Seedance 异步链路验证，不将其包装重绘结果冒充 exact-main 成片。
9. 通过项目 Hermes/DeepSeek 自然语言输入继续该 task，验证 agent loop 能读取 durable state。
10. 输出可播放文件、QA Report、调用链和用户验收入口；用户亲自决定通过、修改或拒绝。

当前步骤 2–9 被租户级策略阻塞。允许的安全替代是：用户在 Codex 之外自行完成 Provider
调用，并把去除密钥/请求头/个人数据后的结果文件放入明确的本地验收目录；Codex 只执行
本地导入、hash、合成、QA、返修判定和文档更新。不得由 Codex 生成或运行外呼脚本。
