# Redundancy Review

## 工作流

1. 搜索项目中的已有实现和相似命名。
2. 搜索已有接口、服务、数据模型和配置。
3. 搜索未完成、禁用、TODO 或尚未接线的实现。
4. 检查 Git 历史中是否曾实现、重命名或删除类似能力。
5. 比较职责、调用方、数据所有权、生命周期和扩展点。
6. 分类：`REUSE`、`EXTEND`、`REFACTOR_EXISTING`、`REPLACE` 或 `CREATE_NEW`。
7. 输出重复风险、推荐方案、理由和影响文件。

## 决策规则

- `CREATE_NEW` 前必须说明现有能力为何不能复用或扩展。
- 不得仅因现有代码“不够漂亮”就创建第二套平行实现。
- 不得同时保留两套职责相同的服务。
- 替换时说明迁移路径和安全退役条件；未经授权不删除旧实现。
